# Architecture (v1.15)

## Lexique (S4.5) — un mot par concept, à l'écran, dans l'aide, le README et les textes du jeu
- **Ambient** : l'instrument (en-tête, LCD). **Parcours** : le jeu (jamais « Jardin sonore » à l'écran). **Mode libre** : tout ouvert.
- **Jardin** : seulement le visuel où pousse une plante par couche (Parcours). **Arbre** : la carte du Parcours ; un nœud est **ouvert**, **prêt** (réussi, attend que le joueur touche « ✦ Ouvrir »), **à ouvrir** ou **fermé** (pas « débloqué », « acquis »).
- **Défi** (◇ sur le LCD) : ce qui ouvre un nœud (pas « contrat »). **Réponse** (↺) : rejouer une phrase entendue (`kind: 'reponse'`). **Secret** (✦). ✓ = réussi ; ✦ = nouveau (nœud ouvert, secret, paysage généré, remise).
- **Paysage** : un son complet (menu Paysage, ✦ Nouveau paysage, Mes paysages, lien partagé ; pas « patch », « preset », « Son »). **Timbre** : le son d'une couche.
- **Lumière** : sombre ↔ clair (grand réglage, réglage de chaque couche, glisser horizontal, CC74 ; pas « Couleur », « Brillance »). **Gamme** : les notes (pas « couleur »).
- **Grands réglages** : Lumière, Densité, Espace, Nostalgie, Nature (pas « macros »). **Couche** : Drone, Pad, Mélodie auto, Grains, Texture (+ Mélodie écrite, Basse, Pulsations).
- **Écho** : l'effet et son nœud, rien d'autre. **Temps** : Pulsé / Flottant ; **Rythme** : le nœud Composer (basse, pulsations, groove). **Composer** : le mode, ouvert par la branche du même nom.
- **Plein écran** (⤢) ; **Écouter** : le mode. Ids internes inchangés quand ils sont invisibles (`#preset`, `patches` des exports, `macro.*`, `#p=`, `e.echo`), pour les sauvegardes et les liens.

Scripts classiques, pas de build. État global `window.AMB`. Un module = un IIFE qui pose `AMB.<nom>` (ordre de chargement = `index.html`). Bus : `AMB.bus.on/emit` (js/sequencer.js). Réglages : `AMB.store` (js/params.js, schéma `AMB.SCHEMA`).

Règle de produit (v1.05) : le jeu se joue SUR l'instrument (ses commandes, son son, son écran). Pas d'écran de jeu à part, pas de mini-jeu hors de l'instrument.

notes jouées lecture arrêtée (aussi A–L) via `engine.liveInput` : petit chemin après le fondu d'arrêt (`out`) ; le bouton MIDI (barre, visible si Web MIDI existe) réveille l'audio en silence et se reconnecte seul si le MIDI est déjà autorisé ; - Parcours (fichiers `garden*` : ancien nom « Jardin sonore » ; S4.3 sans monnaie) : `game.js` (état, nœuds ; `ready(id, by)` met un nœud dans la file des prêts, `open(id?)` l'ouvre (le premier ouvrable par défaut), `unlock(id, by)` ouvre sans condition), `tree.js` (arbre en données, verrous ; état d'un nœud : ouvert / prêt / peut s'ouvrir / fermé ; `EXPLAIN` = le texte simple de chaque nœud ; `appear` = l'arrivée animée de ce qu'un nœud ouvre), `garden.js` (accueil, défi sur le LCD, retours de la Réponse sur le LCD, actions `act`, carillon, séquence d'ouverture, messages LCD, fin), `garden-tree.js` (écran Arbre, une carte : chaque nœud dit ce qui l'ouvre), `contracts.js` (défis et portes à Réponse ; table `OPENS` nœud → défi ; un à la fois, dans l'ordre du parcours), `puzzles.js` (« Réponse », S4.2 : la phrase marquée dans la musique), `secrets.js` (table `OPENS` : un secret rend prêt son nœud, prérequis compris, ou, déjà ouvert, le nœud suivant du parcours ; l'indice 2 s'ouvre après 2 secrets), `garden-visual.js` (visuel Jardin ; la plante Mélodie montre la Réponse). CSS : tout dans `css/style.css`. `tests/game.html` vérifie que `sw.js` précache tout `index.html`, dans l'ordre (ASSETS + CACHE à mettre à jour). `tests/narrow.html` : à 390 px, aucun mode d'écran ne dépasse la largeur.

## Bus (événements)
- `live` {midi, time, vel (entendue), raw (vélocité MIDI brute 0..1, null au clavier)} · `chord` {time, deg, midis, forced (accord joué par le joueur)} · `phrase` {i, len, time} · `section` {index, name}
- `liveOff` {id, midi, time} (fin d'une note tenue) · `panic` {} (arrêt de la lecture : toutes les notes tenues finissent, pédale relevée)
- `note` {layer, midi, time, vel, dur, live (voix jouée en direct ou phrase de la Réponse)} · `perc` {track, time, vel} · `grain` {layer, midi, time, vel} · `freeze` {}
- `act` 'id' (action réussie, comptée par les défis : save, keep, restore, chord, freeze, xy, dice, sceneStore, sceneRecall, songRec (● Rec du morceau mené à son terme) ; midiConnect = un clavier MIDI est là) · `rec:done` secondes (● Rec de la barre, ou ● Rec du panneau Morceau mené à son terme ; rien à l'annulation)
- `game:*` ready {id, by} (S4.6 : nœud gagné, en attente du joueur), unlock {id, by (id du défi qui l'ouvre, sinon null)}, contracts {id} (défi réussi), contract (défi en cours, progrès), puzzle (Réponse : {phase: 'call' (avec `ans`, début de la mesure de réponse) | 'note' {i, peg} | 'end' {res : null si ignorée ou annulée, sinon {ok, len, row, next, streak, gate, open, out, left}}}), secret {id}, mode, reset

## Store (sources de `store.set(k, v, source)`)
- `user` = la seule qui compte (défis, secrets) ; l'annulation enregistre `user`, `preset`, `macro`.
- `preset`, `macro`, `undo`, `sync` (position des macros recalculée, muette), `xy` (pad XY et CC MIDI), `morph` (scènes, morceau), `evolve` (Dérive), `lfo`, `game` (verrous de l'arbre, cadeaux).
- Jargon (S4.3) : en Parcours, avant Tonalité (`h.key`), `body.jargon-off` cache le nom du paysage, la tonalité, la gamme, le tempo et l'accord (LCD « AMBIENT »). Glisser sur l'écran (`perform.setMacro`) marche dès la Graine, les 5 boutons des grands réglages restent fermés ; S4.5w : en Parcours, le premier glissé lecture arrêtée lance aussi la lecture (en libre, rien ne change).

## Défis et Réponse (S3.6, S4.3, S4.2)
- Chaque nœud a un seul défi qui l'ouvre (`contracts.OPENS`, 31 nœuds) ; un défi n'est proposé que si son nœud peut s'ouvrir et que ce qu'il joue est là (`need`). File déterministe : l'ordre d'`OPENS`, les défis passés (↷) en dernier ; le dernier défi (« Enregistre ton morceau », `first`) n'ouvre aucun nœud. Rythme : `tests/balance.html` (S4.6 : 8 s par nœud pour lire et ouvrir, au rythme du joueur, comptées à part ; parcours type joué ≤ 45 min, jamais 3 min sans nœud, aucun ordre bloquant).
- « Réponse » (S4.2, `puzzles.js`, sans carte ni écran) : pendant la lecture, en Parcours, dès la Mélodie auto, le séquenceur appelle `puzzles.onStep` à chaque pas ; sur une barre de mesure, une phrase marquée (rng du jeu) est jouée sur la grille par la voix Mélodie, la plante Mélodie clignote, puis le LCD dit « ↺ À toi » à la mesure suivante. Le joueur la rejoue (A–L, pastilles, MIDI à n'importe quelle octave) : une feuille par note sur la plante (verte = juste, rouge = fausse ; au moins 4 px CSS par carreau, la tige s'allonge pour les porter si la plante est petite ; elles suivent la croissance S4.5w). Les notes jouées pendant la phrase ne comptent pas. S5.3, sans plafond : une réussite = un niveau de plus, un raté = un de moins (`puzzles.level(lvl)`, une seule table `TIERS`) : Phrases de 3 à 8 notes (3–4 sur les temps ; dès 5, rythme sur les croches jugé au placement, `live`.played = `seq.playedAt`, tolérance ±1,2 double-croche), puis paliers nommés : Octaves (un saut d'octave dans A–L ; la 1re note fixe l'octave, le saut doit être joué), Syncopes (au moins la moitié des notes entre les temps), Quinte (rejouer la phrase une quinte plus haut, toujours dans A–L), Accords (la Mélodie joue 1 puis 2 accords : à la main dans les 0,35 s, tout renversement et toute octave, ou forcés par appui long / notes graves, bus `chord` forced), puis Combinaisons +k (octaves ou quinte, syncopées, tolérance × 0,9^k). LCD (Parcours seulement) : 3e ligne `#lcdScore` « ↺ PALIER · SÉRIE n · RECORD n » (`garden.renderScore`) ; « ↑ Palier : X », « ★ Record », « ✓ Juste · série n » avec juice (S5.9 : recettes `streak` / `record` / `tier` de la table `FX`, voir « Juice central »). Plante Mélodie : `puzzles.mark()` LED sous son nom (`gardenVisual.drawMark`), un par palier. Bus pour un juice central : `resp:streak` {streak}, `resp:record` {best}, `resp:tier` {tier, name, lvl}. Sans rythme, la fenêtre de réponse dure au moins 2 mesures ou 6 s. Une phrase ignorée ne change rien, la suivante attend plus longtemps (4 mesures, puis 8, jusqu'à 16). Rien à l'arrêt, en libre, après la remise, ni pendant le Rec live ; sans porte, seulement si la Mélodie est allumée. État sauvé : `game.s.resp` {lvl, len (longueur du niveau, gardée pour les anciens lecteurs), streak, best (record de série), beat, miss} ; une ancienne sauvegarde {len, best = longueur} repart de sa longueur, record = sa série.
- Portes à Réponse = défis `kind: 'reponse'` (6 : Premier reflet → Grands réglages, Suite connue → Phrases, Boîte à musique → Mélodie écrite, Autre lumière → Progression, La grotte → Usure, Pluie de notes → Mouvements lents ; `need` contient la Mélodie). Porte en cours : sa phrase vient à la mesure suivante, de `min(len, N)` notes, N = 3 jusqu'à la profondeur 3, 4 au-delà (`puzzles.need`), jamais en rythme ; une réponse juste de N notes ouvre le nœud ; 6 ratés l'ouvrent quand même. LCD : « ↺ Réponse : <titre> · N ♪ », toucher = l'aide.
- Pendant une Réponse en attente (`puzzles.busy()`), aucun secret n'est détecté ; les notes comptent encore pour le défi en cours (un seul défi à la fois). La Mélodie auto se tait de la phrase à la fin de la réponse (`puzzles.hush`, via `seq.melodyNote`) ; le reste de l'ambiance n'est pas touché. Captures : `tests/shot-tree.html#reponse` et `#reponse-leaves`.

## Composer et remise de l'instrument (S3.5, S3.7)
- Composer = 3 nœuds : Mélodie écrite (`c.seq` : piano roll, arpège, motifs, Rec live), Rythme (`c.rythme` : basse, pulsations, groove), Morceau (`c.song` : sections, automation, Rec du morceau). `game.load()` remplace les anciens ids (`game.MERGED` : c.arp, c.motifs → c.seq ; c.bass, c.perc, c.groove → c.rythme ; c.auto → c.song).
- Défis Composer joués : 6 notes en Rec live, un groove de basse qui tourne 4 mesures (événements `note` de la basse), « Enregistre ton morceau » (`act` songRec). Ce dernier (`first`) passe avant les autres dès que Morceau est acquis.
- Remise (`garden.checkEnd`) : arbre complet → le dernier défi d'abord ; une fois fait ou passé (↷) : `game.s.ended` (sauvegardé), carillon, « L'instrument est à toi » sur le LCD, puis la ligne de défi disparaît (`garden.handedOver()`). Le store n'est pas touché. Ensuite `game.counts()` est faux ; l'arbre reste consultable. Les secrets restent à trouver (`secrets.active()` : Parcours, hors Réponse en attente) : cadeau, carillon et LCD, sans nœud ; le panneau ne montre que les secrets trouvés.
- Vraie fin (S4.5w) : quand « Enregistre ton morceau » finit le Parcours, `rec.js` confie le WAV à `garden.keepSong` (au lieu de le télécharger) ; `garden.finale` le relit dans l'instrument (sortie directe, jamais réenregistrée ; le son en direct s'efface puis revient) : extrait de `REPLAY` = 18 s (morceau entier s'il dure ≤ 22 s ; sinon la fenêtre où jouent le plus de couches), le Jardin passe de la nuit à l'aube, chaque plante s'allume quand sa couche joue (événements du bus notés pendant l'enregistrement, `garden.tape`, temps depuis `rec.songT0()`). Puis « L'instrument est à toi » et la ligne du LCD propose « ⤓ Garde ton morceau (WAV) » (↷ = non merci ; non sauvegardé). Le Jardin reste à l'aube une fois l'instrument remis. ↷ sur le dernier défi : remise sans relecture. ■ Stop (`panic`) arrête la relecture (fondu de 0,15 s), puis la remise.

## Ouvrir est le geste du joueur (S4.6)
- Un défi, une Réponse ou un secret réussi n'ouvre plus rien : `contracts.finish` et `secrets.find` appellent `game.ready(id, by)` (un secret met d'abord ses prérequis manquants dans la file). État sauvé : `game.s.ready` [{id, by}], dans l'ordre ; `tree.status` = `'ready'`. La réussite est fêtée sobrement (`chime('solve')`, LCD « ✓ Défi réussi » / « ↺ ✓ Juste ! » ; un secret : « ✦ Secret : <titre> »).
- Tant qu'un nœud est prêt : aucun défi (`contracts.refill` vide `active`, le progrès reste dans `prog`), la 2e ligne du LCD est « ✦ Ouvrir : <nœud> » (`game.nextReady()`, pulse ; « N prêts » s'il y en a plusieurs ; pas de ↷), ✦ sur le bouton Arbre, « ✦ prêt » et un bouton ✦ Ouvrir dans la fiche de l'arbre. Toucher → `garden.ask(id)` : la carte `#openDlg` dit ce que le nœud apporte (`tree.EXPLAIN`, une ou deux phrases pour un enfant non musicien, la seule table de ces textes), « Ouvrir » → `garden.openNode(id)` → `game.open` → la séquence d'ouverture ci-dessous. Rien ne disparaît sur un minuteur avant que le joueur agisse (l'aide d'un défi reste jusqu'au toucher suivant).
- Ce qui sort d'un verrou (`tree.applyLocks(g, live)` sur `game:unlock`, sauf la Graine) entre par `tree.appear` : `is-appearing` (déploiement en hauteur par clip-path, fondu, léger zoom, 0,55 s) sur les plus extérieurs, `is-new` (halo qui pulse) sur les contrôles jusqu'au premier toucher (pointerdown / change) ou `NEW_MS` = 8 s, étiquette « Nouveau ▾ » (`is-new-first`) sur le premier. `tree.hold()` / `release()` les retient pendant la séquence de la carte (`seqFinish`). Mouvement réduit : ni déploiement ni pulsation, halo et étiquette fixes.
- Anciennes sauvegardes : un nœud ouvert le reste ; une réussite enregistrée sans nœud ouvert (défi dans `contracts`, secret dans `secrets.opened`) devient prête (`contracts.migrate`, `secrets.migrate`). Mode libre : rien de tout cela.

## Le déblocage calé sur la musique (S4.5w)
- `garden.beat(id)` (à chaque nœud ouvert en Parcours, S4.6 : quand le joueur touche « Ouvrir ») : `strongBeat()` = prochain temps 1 ou 3 de la mesure (pas de 16e comptés depuis `seq.origin`), au moins 0,45 s devant, sur l'horloge audio ; lecture arrêtée : tout de suite. La couche du nœud (`gardenVisual.LAYERS[].node`) reste à 0 jusqu'au temps fort puis entre en fondu (`FADE` 1,6 s, gain du canal) ; le carillon y est placé (`chime(kind, {at, deg})`, une note propre à chaque couche, `LAYER_DEG`, dans la gamme) ; sur la carte, l'impact de la séquence tombe dessus.
- `garden-visual.js` : la plante nouvelle (ou grandie) POUSSE en 1,2 s (échelle Y du sprite en cache) à partir du temps fort, ou de la fermeture de la carte si elle est plus tard (`growAt` / `retime`) ; le ciel suit l'accord (`chord`) et la gamme (teinte par degré, mineur plus sombre ; ciels en cache, fondu de 2 s par globalAlpha) ; le sol pulse au tempo (temps 1 et 3 plus forts). Mouvement réduit : pas de croissance ni de pulsation (le ciel suit). Coût mesuré par `tests/garden-visual.html` (1280×800, tout animé) : ~0,3 ms par image en moyenne, p95 ~0,4 ms.

## Les plantes montrent les réglages (S4.6)
- Une seule table, `LOOK` / `LOOK_ALL` en tête de `garden-visual.js`, indépendante du dessin : réglage → 7 aspects 0..1 par plante (`look(get)`, pure). Niveau (× Volume général) → taille ; Lumière (× Usure / Cassette) → couleur, éclat, pétales ouverts ou bouton fermé ; Timbre (Type pour la Texture, Kit pour les Pulsations, Taille pour les Grains) → pétales ronds ↔ pointus (4 à 7 pointes), feuilles lisses ↔ dentelées ; Espace de la couche × Reverb (+ Halo) → halo ; mouvement de la couche (Mouvement, Attaque, Résonance, Swing +, Flou, Tenue) → ampleur de l'ondulation, Tempo (Flottant = plus lent) → sa vitesse ; Densité, Accords riches, notes du motif, coups du rythme → 1 à 4 fleurs. Les grands réglages passent par les réglages qu'ils bougent (`perform.MACROS`). Un autre décor (ville) relit les mêmes aspects : seul `dress` / `tones` / `frame` changent.
- Le Jardin écoute `store.on` : la forme suit en ~0,4 s (lissage exponentiel, sans saut) ; source `user` / `macro` / `xy` = impulsion sur les plantes concernées (`concerns(key)`) : rebond amorti, ondulation plus ample, plante éclairée tant qu'on touche (+0,6 s). Un curseur tenu = un seul rebond puis la plante suit. Dérive, LFO, paysages, scènes : la forme suit, sans impulsion. Hors écran : rien n'est gardé.
- Taille (v1.14, `sizeK`) : ×1 au réglage par défaut de la couche (la taille d'avant S4.6), ×0,5 au Niveau 0, ×`SZ_MAX` = 1,3 au maximum ; la hauteur est plafonnée sous le HUD de l'écran, la largeur à mi-chemin des plantes voisines (`roomL` / `roomR`, calculés au `refresh`) : à 390 px, tout au maximum, aucune fleur ne passe sur sa voisine (`tests/garden-visual.html`).
- Sprites en cache par aspects quantifiés (5 formes × 5 lumières × 1–4 fleurs) ; taille, halo (8 rayons en cache) et ondulation dessinés en continu. Mouvement réduit : formes et taille tout de suite, ni rebond ni ondulation. Coût (`tests/garden-visual.html`, curseurs bougés à chaque image) ~0,3–0,4 ms par image, p95 ~0,4 ms. En libre : rien ne change (le Jardin n'y existe pas).

## Chaque note se voit (S5.2)
- Le Jardin reste un reflet : rien n'y est touchable. Déclenchement séparé du dessin, en tête de `garden-visual.js` : `splash(ev, d)` (pur) → {plante, qui (joueur / accord / machine), vélocité, hauteur 0..1, tenue, secousse} ; table `SPLASH` par « qui » ; un seul bouton d'intensité, `JUICE` (1 = généreux et un peu goofy). Le dessin (`fire`, `drawSplash`) est seul à changer pour une autre esthétique.
- Joueur (`live` : A–L, pastilles, MIDI ; plante Mélodie écrite pendant le Rec live ; accord forcé = Pad) : anneau de LED, lueur à la hauteur de la note sur la tige (tenue = allumée jusqu'à `liveOff`, fondu de 0,35 s), particules, éclair, squash & stretch ; secousse de la scène sur un accord forcé ou une note MIDI forte (≥ 0,85). Machine (`note` non live de Mélodie auto, Mélodie écrite, Basse ; `perc`) : la même chose, bien plus petite. Au plus 3 ondes par plante (la machine ne chasse jamais le joueur), 260 particules au plus. Mouvement réduit : une lueur fixe de 0,3 s (ou tant que tenue), sans onde, particules, rebond ni secousse.
- Pastilles (`play.js`) : une note de la Mélodie auto (`note` bells non live) allume 0,17 s la pastille de la même note, la plus proche en hauteur (`padForMidi`), de sa couleur (`.pad.auto`). La phrase de la Réponse est `live` : elle n'allume rien. Coût (`tests/garden-visual.html`, 8 notes jouées / s + accord / s + machine) ~0,3 ms par image.
- Fêtes de la Réponse (S5.3, via `garden.FX`, S5.9) : même système, lignes `streak` / `record` / `tier` de `SPLASH` sur la plante Mélodie (plus de particules, rebond plus ample ; record et palier secouent la scène), même `JUICE`. Il n'y a qu'un réglage d'intensité pour tout le juice du Jardin.

## Juice central (S5.9)
- Une seule table, `garden.FX` (garden.js) : moment → recette. Moments : `first` (contrôle « Nouveau » touché la 1re fois, tree.js), `juste`, `ready` (nœud prêt), `streak`, `defi` (défi ou Réponse-porte réussi), `record`, `secret` (secrets.js), `tier`, `open` (nœud ouvert, sur son temps fort, note et plante de sa couche), `end` (remise), `discovery` (énorme, pour S5.10 : `garden.fx('discovery', {name})`). `garden.FX_ON` = les événements du bus qui sont des moments (`game:ready`, `game:contracts`, `resp:*`) ; les autres appellent `garden.fx(kind, o)` là où ils arrivent. Plus aucun carillon ni toast de fête ailleurs (`garden.cheer` supprimé, carillon de la carte retiré de `seqImpact`).
- `fx` écrit tout de suite le message (LCD `say`, `toast`), puis les moments du même instant fusionnent (microtâche) : le plus gros (`rank`) joue seul. `fxPlay` place le jingle (`chime`, `JINGLES`, dans la tonalité) et les éclats S5.2 (`gardenVisual.cheer(kind, at, plant)`) sur l'horloge audio du temps suivant (`strongBeat(…, 4)`, ou le temps fort de l'ouverture), le reste au même instant par minuteur : flash de la scène (`.fx-flash`), confettis pixel (`garden.confetti` : un canvas fixe `#fxLayer`, pointer-events: none, caché au repos, 700 au plus, dessiné seulement pendant le vol), secousse (`.stage.fx-shake` ; 2 = aussi les enfants de `.app`, jamais `.app` elle-même qui tirerait les boîtes fixes), LCD (`lcd-glitch`, `lcd-glitch-big`, `lcd-arcade` = message qui défile et clignote), boutons qui sautent (`body.fx-bounce`, `.fx-hop`), punch du visuel (`#viz.fx-punch`), texte combo (`.fx-pop`). Propriétés `translate` / `scale` / `rotate` : rien ne se bat avec le `transform` d'un élément.
- Intensité : `JUICE` de garden-visual.js (seul réglage, `garden.juice()`). Mouvement réduit : flash doux seulement (+ jingle, message). Libre : `fx` ne fait rien. Coût (`tests/juice.html`, `discovery` + Jardin + notes) : confettis ~0,1 ms par image (p95 ~0,2), ~0,45 ms avec le Jardin. Captures : `tests/shot-tree.html#juice-defi` / `#juice-open` / `#juice-tier`.

## Chaque bouton a un impact visuel (S5.8)
- Deux tables en tête de `garden-visual.js`, indépendantes du dessin : `LOOK` (plantes, S4.6 ; + aspect `on` : couche coupée = plante éteinte) et `SCENE` (calques de la scène).
